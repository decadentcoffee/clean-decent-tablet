# Debloating

## What disabling means

`adb shell pm disable-user --user 0 <package>` turns an app off for Android user 0. The app stays on the
tablet but cannot run, show notifications or appear in the app drawer. `adb shell pm enable --user 0 <package>`
turns it back on. Nothing is deleted, and no app data is lost.

Disabling stops that app's own background work. It does not stop other system services from sending data.

The scripts never assume user 0: they ask the tablet for the current user (`am get-current-user`).

## How packages are chosen

Every installed package has a row in `manifests/packages.csv`:

| Column | Meaning |
|---|---|
| `original_state` | enabled or disabled at the first snapshot (Decent's shipping state) |
| `category` | `KEEP`, `CANDIDATE` or `INVESTIGATE` |
| `proposed_action` | `keep`, `disable` or `investigate` |
| `batch` | which small batch it belongs to |
| `approval` | `pending` until the owner approves; the scripts act only on `approved` |
| `verification`, `tested_model_build` | filled in after the batch passes the checks below |

`scripts/lib.sh` holds a protected list (Settings, System UI, Bluetooth, Wi-Fi, WebView, package installer,
permission controller, Play services, Play Store, Chrome, One UI Home, the keyboard, Decaid, AndroWish, updates).
The scripts refuse to disable those, and also refuse the current Home app and current keyboard, even if the
manifest says otherwise.

## Steps for one batch

1. Review the batch rows in `manifests/packages.csv`. Set `approval` to `approved` for each package you accept.
2. Dry run: `scripts/disable.sh --batch <n>`. Read the `plan` lines.
3. Apply: `scripts/disable.sh --batch <n> --apply`. Type `yes`.
   The script checks the tablet's model and build against `manifests/device.expect`, takes a fresh snapshot,
   then disables one package at a time and stops at the first failure. Every change goes to `logs/changes.tsv`.
4. Run `scripts/verify.sh`.
5. Do the manual checks:
   - Press Home. The launcher appears.
   - Open the app drawer.
   - Open Settings.
   - Type in a text field. The keyboard appears.
   - Start Decaid. It connects to the DE1. Do not start a shot.
   - Open Decadent from the home screen.
   - Let the screen sleep, then wake it.
   - Reboot, then repeat these checks.
6. If a check fails, undo the batch: `scripts/rollback.sh --batch <n> --apply`. Then investigate one package at a time.
7. If all checks pass, fill in `verification` and `tested_model_build` for the batch.

## Undo

`scripts/rollback.sh` reads `logs/changes.tsv`. It re-enables only packages this project disabled, and
never one in `manifests/original-disabled.*.txt`. Options: `--batch <n>`, `--package <id>`, `--apply`.
It is safe to run twice.

## Do not reboot straight after a batch

Android saves package state a few seconds after a change. A reboot right after a batch brought the last 5 of 24 packages back
(seen 3 Nov 2026). `disable.sh` waits 30 seconds before it finishes. Run the reboot check after that.
